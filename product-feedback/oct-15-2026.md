Right now it reads like an execution log. Here's a quick first step we could ship without new backend work, assuming the events we already get are enough:

## Landing in Frontend

https://shottr.cc/s/2F9i/SCR-20261015-mhs.png

This page asks the user to take in too much, especially right after they click "Generate Frontend". At that point they probably expect a built app, not another screen to review.
The map tree is read-only. ⚠️ **Decision needed:** should users be able to add more screens by upgrading?

Design directions shouldn't appear here. Users can choose a direction better once they've seen the generated frontend (prototype). By default, Archie should apply the direction it considers the best fit, and users can customize it later.
Is also weird the column/bottom interactionm, it's difficult to understand. The content shifts between a column and bottom panel, while the expand/collapse control suggests a different behavior than what actually happens.
Clicking if each option doens't bring any feedback to the user, so is very dificult to make a decision even for an experienced user, in this step, that should be a gratification step instead of a continuation of decisions needed. This is step should be the first moment of truth.

Archie can automatically apply the design direction it believes is most appropriate. The generated frontend then becomes the decision surface.
From there, users can review screens, change the visual direction, add or modify screens, and iterate conversationally.

The flow becomes: Plan → Generate → See the result → React → Refine
rather than: Plan → Generate → Review → Configure → Decide → Generate again
