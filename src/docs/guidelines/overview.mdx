# Guidelines

Components tell you what each piece looks like. These guidelines tell you how the pieces behave **together**: how a removed row leaves a table, where a layout changes at a breakpoint, how to read a Figma value. Each rule was settled with design, so follow it instead of re-deciding it screen by screen.

## One quality bar for every product

Every Archie product is designed to be intuitive, efficient and human. That bar is the same for customer-facing screens and for internal or operational tools. Don't reach for a lower-effort pattern (skipping states, motion or copy quality) because a screen is internal-only.

## How each rule is written

- **Rule:** what to do, in plain language.
- **Why:** the reason, so you can tell a deliberate choice from an accident.
- **For developers:** the token, helper or prop that implements it, and what not to hand-roll.
