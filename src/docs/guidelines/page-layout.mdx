# Page layout

## Breakpoints include their own width

**Rule:** a breakpoint covers widths up to **and including** its frame width. So a window exactly 1024px wide gets the "1024 and below" layout, and the next layout starts at 1025px. In specs and comments, say "at `lg` (1024) and below" or "above `lg`", not "below `lg`" or "from `lg`".

| Token | Frame (W × H) | Tailwind variant starts at | Alignment |
| --- | --- | --- | --- |
| `md` | 768 × 600 | 769px | Tailwind default width |
| `lg` | 1024 × 768 | 1025px | Tailwind default width |
| `xl` | 1280 × 800 | 1281px | Tailwind default width |
| `2xl` | 1536 × 900 | 1537px | Tailwind default width |
| `2.5xl` | 1728 × 972 | 1729px | Custom |
| `3xl` | 1920 × 1080 | 1921px | Custom |

The 1728px frame sits halfway between 1536 and 1920. `sm` (640, from 641px) is also registered for small mobile-to-tablet splits, but it isn't a design review frame.

**Why:** designs are reviewed at those exact frame widths, and each frame has to show the layout designed for it. With Tailwind's default breakpoints, a frame at exactly 1024px got the next layout up.

**For developers:** `theme.css` registers each Tailwind breakpoint 1px past its frame (`--breakpoint-lg: 1025px`), so write the usual classes: `lg:` means above 1024 and `max-lg:` means 1024 and below. Never write an arbitrary `min-[1025px]:`. `2.5xl` is registered as `--breakpoint-2\.5xl` with the dot escaped, because `--breakpoint-2_5xl` would only generate `max-2.5xl:`. In JavaScript, use `mediaAbove("lg")` from `@/lib/breakpoints` with `useMediaQuery` from `@/lib/hooks/use-media-query`, not a hand-written media query. Keep `theme.css` and `src/lib/breakpoints.ts` in sync.

⚠️ **Constraint:** `theme.css` ships to consumers as `@jcaunedo/archie-ucl/styles`, so apps' own `sm:` to `3xl:` classes follow these boundaries too.
