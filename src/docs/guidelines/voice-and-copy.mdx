# Voice and copy

## Three product names, never interchangeable

**Rule:** write **Archie** with a capital A and the rest lowercase, everywhere: UI copy, alt text, stories, docs, specs and comments. Never "ARCHIE", except where CSS uppercases a label. The three product lines are separate:

| Name | What it is |
| --- | --- |
| **Archie** | The flagship full-stack app builder |
| **Archie Core** | The backend-only tier of Archie |
| **Archie Labs** | The professional services arm |

**Why:** each name is a separate product with its own audience, so mixing them up sends people to the wrong one.

**For developers:** when copy says "Archie" and the context could mean Core or Labs, ask which one. Identifiers that aren't user-facing (the `@jcaunedo/archie-ucl` package, the `archie-ucl` repo, CSS and JS names) keep their lowercase forms.

## Brand voice

**Rule:** Archie's UI is **clear, calm and confident**. Use plain words and short sentences, and say what's happening. It never sounds like hype, jargon, cute or blaming.

**Who reads it:** builders (founders, product teams and developers creating apps with Archie), team admins, internal operators, and end users of generated apps. The same voice applies to all of them.

| Use | Not |
| --- | --- |
| blueprint, module, user type, service, tech stack, prototype, app | synonyms for the same object ("project", "plan", "spec") |
| social sign-in (Google, Microsoft, Github buttons) | SSO, which means enterprise SAML/OIDC |

**Why:** Archie's position is clarity before code, so the copy has to show that clarity. The calm tone matches the motion personality.

**For developers:** ⚠️ **Decision needed:** tone per audience isn't defined yet. Until it is, use the one voice above for everyone.
