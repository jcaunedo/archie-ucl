# Button

Triggers an action or event, such as submitting a form, opening a dialog, or moving to the next step.

## Variants

Use one `default` button per view for the primary action. Use `secondary`, `outline`, or `ghost` for supporting actions. Use `destructive` only for actions that delete or cannot be undone.

<Canvas of={ButtonStories.AllVariants} />

| Variant                 | Figma                | When to use                                        |
| ----------------------- | -------------------- | -------------------------------------------------- |
| `default`               | Solid · Brand        | The main action in a view                          |
| `secondary`             | Flat · Brand         | A supporting action next to a primary button       |
| `outline`               | Outlined · Neutral   | A neutral action that needs a visible boundary     |
| `ghost`                 | Ghost · Neutral      | Low-emphasis actions in toolbars and dense layouts |
| `link`                  | Link · Brand         | An action that should read like inline text        |
| `destructive`           | Solid · Destructive  | Delete, remove, or other irreversible actions      |
| `destructive-secondary` | Flat · Destructive   | A quieter destructive action, such as Remove       |

## Sizes

<Canvas of={ButtonStories.Sizes} />

Sizes follow Figma: `xs` (24px), `sm` (28px), `md` (32px, the default), `lg` (36px) and `xl` (40px). Each has a square icon-only size, `icon-xs` to `icon-xl`. An icon-only button has no visible label, so always set `aria-label`.

## With an icon

Place icons from `lucide-react` as children. The button sizes them for its size (16px at `md`). Mark the icon `data-icon="inline-start"` before the label or `data-icon="inline-end"` after it: that side gets Figma's tighter padding. Mark decorative icons with `aria-hidden="true"`.

<Canvas of={ButtonStories.WithIcon} />

## Pending

Set `pending` while the work the button started is running. A spinner covers the label (Figma's Loading state); the label keeps its space, so the button doesn't change width. The button stays focusable, ignores more clicks and sets `aria-busy`, and its accessible name is still the label. The label can change ("Generate app" → "Generating app"), but keep it about the same length so the button doesn't jump.

<Canvas of={ButtonStories.Pending} />

When the work can be cancelled, show a separate Stop button next to the pending one. Don't turn the pending button into Stop: it's a different action with its own handler.

<Canvas of={ButtonStories.PendingWithStop} />

## Disabled

`disabled` removes the button from the tab order and ignores the pointer. Use it only when the reason is obvious.

<Canvas of={ButtonStories.Disabled} />

When people need to know why a button is unavailable, use `aria-disabled="true"` instead. The button stays focusable and keeps its tooltip, and clicks are ignored. Point `aria-describedby` at the text that explains why.

<Canvas of={ButtonStories.FocusableDisabled} />

## In a form

Button defaults to `type="button"`, so it never submits a form by accident. Set `type="submit"` on the button that should.

<Canvas of={ButtonStories.InForm} />

## Long labels

A button never grows past its container. To cut a long label with an ellipsis, wrap the text in `<span className='truncate'>`. Prefer a shorter label first.

<Canvas of={ButtonStories.LongLabel} />

## As a link

Set `asChild` to render the button styles on the child element instead of a `<button>`. Use this for navigation, so the element stays a real link. `aria-disabled` also works here and blocks the navigation; `pending` only sets `aria-busy`.

<Canvas of={ButtonStories.AsLink} />

## Accessibility

- Renders a native `<button>`, so keyboard and screen reader support work out of the box.
- The focus ring uses the `--ring` token and appears only on keyboard focus.
- Icon-only buttons need an `aria-label`.
- `pending` sets `aria-busy` and keeps the label as the accessible name, under the spinner. If people need to hear when the work finishes, announce the result in a `role="status"` region.
- Prefer `aria-disabled` over `disabled` when the reason matters: a `disabled` button can't be focused, so its reason is never read out.
- Use `asChild` with an `<a>` for navigation. Do not use a button with an `onClick` that changes the URL.
